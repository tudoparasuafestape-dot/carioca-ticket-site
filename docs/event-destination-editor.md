# Universal destination editor and public consumer — dependent draft

Requires the separate backend destination endpoints. Do not publish this operational page before backend review/approval/deployment. It does not claim all events already have verified coordinates.

Every event card in eventos-v2 gets the same Formato e localização action, including newly created events. Creation keeps its existing secure-draft flow and directs the organizer to that step; destination persistence goes only through the new authenticated token+event endpoints, never through the legacy unguarded create/update functions. Once the responsible person confirms a pin, the public Uber button is automatic for that event with no code change or new registry entry.

The editor reuses the existing portal session without creating permissions. It offers map search for the event's public address, separate decimal coordinate fields and a link to check that precise point. There is no geocoding, extraction of viewport centers, browser geolocation, Uber call, new account or external map request before a user follows the link. Confirmation is cleared whenever a coordinate changes. Revision/signature conflicts require reload. Saving/revoking remains explicit. Google origin, a cryptographically random single-use pending request nonce, and a bounded cross-origin-safe parent chain to the target iframe protect RPC replies. HtmlService posts from a nested sandbox; direct outer-window equality is insufficient. Browser fixtures use real nested frames with all responses fulfilled locally; wrong origin, wrong nonce, unrelated frame and replay are rejected.

Both public templates use the same candidate event-uber consumer. A version1 confirmed payload with matching ID and full location is accepted for any event. Present null/unconfirmed data never falls back to static registry. The existing two-event registry is legacy-only until confirmed records are migrated; no broad fallback or pin copying exists.

Tests: node tests/event-destination-contract.cjs; node tests/event-uber-contract.cjs; node tests/event-destination-browser.cjs. Browser tests intercept all form submissions with synthetic records and block all external traffic. They cover save/reload/revoke, separate events, changed coordinates, conflict+reload, rejected/missing session, and320/390/1440px. Actual organizer auth and storage are backend tests/review, not simulated-browser proof.

Known rollout requirement: pins for existing events must be confirmed in this one-time registration flow. Address text alone is not a reliable entrance coordinate. This universal workflow replaces adding hardcoded exceptions per event; it cannot invent pins for venues whose coordinates are unavailable.

Local actual-script/fake-DOM test: node tests/event-destination-editor-runtime.cjs passed for save/reload/revoke, pin-change confirmation reset, conflict recovery, invalid coordinates and missing session. It is not browser-layout validation.

Explicit format is part of this draft: PRESENCIAL, ONLINE or HIBRIDO, selected and confirmed by the responsible organizer. Online hides physical-coordinate fields and stores no pin; hybrid uses its physical venue. Changing format clears confirmation. Backend governance adds this prerequisite for new governed drafts, preserving ungoverned legacy and already-published events. It does not infer format from address words or free/paid admission. This operational change remains subject to review and separate production approval.
